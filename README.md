## :dart: O guia para alavancar a sua carreira

> QA (Quality Assurance) é quem garante que o software funciona antes que o problema chegue ao usuário: testes manuais, automação com Selenium/Cypress/Playwright, testes de API, performance e a cultura de qualidade dentro do time de desenvolvimento. Este guia reúne roadmap, cursos gratuitos e pagos, documentação oficial das principais ferramentas, livros, canais, sites de prática, certificações (ISTQB) e um capítulo dedicado a usar IA na prática no dia a dia de quem testa software — tudo verificado e organizado para quem está começando na área ou já testa e quer se atualizar.

## 🗺️ Roadmap

- [roadmap.sh — QA Engineer](https://roadmap.sh/qa) — roadmap visual e interativo da comunidade: fundamentos de teste, automação, API, performance e ferramentas, com links por tópico.
- Trilha resumida: fundamentos de teste (tipos, técnicas, ciclo de vida) → lógica de programação → uma ferramenta de automação web (Selenium, Cypress ou Playwright) → testes de API → testes de performance → CI/CD e integração com o time de desenvolvimento.

## 🚀 Por onde começar

1. **Entenda o que é QA e teste de software** — leia o comparativo [Selenium, Playwright, Cypress e TestCafe para Testes Automatizados Web (DEV Community)](https://dev.to/ikauedev/comparativo-profundo-selenium-playwright-cypress-e-testcafe-para-testes-automatizados-web-2o5k) para entender o cenário atual de ferramentas.
2. **Diferencie teste manual de automatizado** — comece pelo manual (planos de teste, casos de teste, bugs) antes de automatizar; a [trilha de Quality Assurance da DIO](https://www.dio.me/articles/trilha-quality-assurance-qa) organiza essa progressão.
3. **Aprenda lógica de programação** — a maior parte da automação de testes é código; o módulo gratuito de [Quality Assurance do freeCodeCamp em português](https://www.freecodecamp.org/portuguese/learn/quality-assurance) já une lógica, JavaScript e testes com Chai.
4. **Escolha sua primeira ferramenta de automação web** — veja a seção [📖 Documentação oficial](#-documentação-oficial) abaixo e comece por Selenium ou Cypress, que têm mais conteúdo em português.
5. **Pratique testes de API** — a [documentação oficial do Postman](https://learning.postman.com/docs/getting-started/introduction/) ensina a testar APIs REST sem escrever automação, um ótimo primeiro passo.
6. **Treine em sites feitos para praticar** — use os ambientes seguros listados em [🧪 Projetos práticos e desafios](#-projetos-práticos-e-desafios) para aplicar o que aprendeu sem medo de quebrar nada.
7. **Construa um portfólio no GitHub** — suba seus scripts de automação, planos de teste e relatórios de bug; isso vale mais que qualquer certificado no início de carreira.

- [TestNG — Documentação oficial](https://testng.org/) — framework de testes para Java inspirado no JUnit, com suporte nativo a testes paralelos e data-driven.
- [pytest — Documentação oficial](https://docs.pytest.org/en/stable/) — framework de testes mais usado em Python, simples e extensível via plugins.
- [Appium — Documentação oficial](https://appium.io/docs/en/latest/) — automação de testes para aplicativos mobile (Android e iOS) e desktop.

## 🤖 IA na prática

IA generativa mudou a forma de escrever e manter testes: em vez de criar cada caso manualmente, dá para gerar casos de teste a partir de uma user story, criar scripts de automação a partir de uma descrição em linguagem natural e detectar regressões visuais que um `assertEquals` nunca pegaria. Use a favor da cobertura, sem abrir mão da revisão — teste gerado por IA também precisa ser revisado como qualquer outro código.

**Geração de casos de teste**
- Cole uma user story ou requisito e peça para a IA (ChatGPT, Claude, Gemini) **gerar casos de teste em formato de tabela** (cenário, passos, resultado esperado), depois revise cobertura de casos negativos e de borda, que a IA tende a esquecer.
- Ferramentas especializadas como o [TestSprite](https://www.testsprite.com/) e o [teste.ai](https://www.teste.ai/) geram cenários e casos de teste de software automaticamente a partir de requisitos ou da própria aplicação.
- Leia [9 Melhores Geradores de Casos de Teste com IA (Apidog, em português)](https://apidog.com/pt/blog/best-ai-test-case-generators-pt-2/) para comparar opções antes de adotar uma ferramenta paga.

**Automação e agentes de navegador**
- O [Playwright](https://playwright.dev/docs/intro) já embarca agentes de IA (Planner, Generator e Healer) que analisam a aplicação, geram testes reais navegando pela interface e corrigem seletores quebrados automaticamente.
- Combine o [Playwright MCP com o Claude Code](https://testomat.io/blog/playwright-mcp-claude-code/) para deixar um agente de IA navegar pela sua aplicação de verdade e escrever testes a partir do que ele observa na página (DOM/accessibility tree), em vez de só ler o código.
- Use o [GitHub Copilot](https://docs.github.com/en/copilot) ou o [Cursor](https://cursor.com/) para gerar automação (Selenium/Cypress/Playwright), massas de dados de teste e documentação de casos de teste a partir de comentários.

**Testes visuais com IA**
- O [Applitools Eyes](https://applitools.com/platform/eyes/) usa "Visual AI" para comparar telas e apontar só as diferenças que um olho humano notaria, reduzindo falsos positivos de testes visuais pixel a pixel.
- A [Test Automation University](https://testautomationu.applitools.com/) tem cursos gratuitos específicos sobre testes visuais com IA.
- Leia [IA na automação de testes: como aplicar Inteligência Artificial para gerar testes automatizados (Softdesign)](https://www.softdesign.com.br/blog/ia-na-automacao-de-testes/) para um panorama em português do tema.

**Limites e boas práticas**
- IA **inventa seletores, nomes de elementos e endpoints de API** que não existem na aplicação real (alucinação). Sempre rode o teste gerado antes de confiar nele.
- Nunca cole dados de clientes, tokens de API ou credenciais reais em prompts de IA — use massas de dados fictícias (Faker, por exemplo) mesmo ao pedir ajuda para gerar dados de teste.
- Teste gerado por IA tende a cobrir só o "caminho feliz"; a responsabilidade de pensar em casos negativos, de borda e de segurança continua sendo de quem testa, não da ferramenta.
- Revise sempre a manutenção: um "self-healing" de seletor pode esconder uma mudança de UI que na verdade é um bug real.

## 🎓 Certificações

- [ISTQB — International Software Testing Qualifications Board](https://www.istqb.org/) — certificação internacional mais reconhecida da área, com os níveis CTFL (Foundation) e CTAL (Advanced).
- [BSTQB — Brazilian Software Testing Qualifications Board](https://bstqb.qa/) — conselho brasileiro membro do ISTQB, responsável pela tradução oficial dos syllabi para português e pela aplicação de provas no Brasil.
- [ABRAMTI — mantenedora do BSTQB](https://abramti.org.br/) — instituição sem fins lucrativos brasileira que mantém o BSTQB e outras certificações de engenharia de requisitos.
